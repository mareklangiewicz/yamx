# Domain docs

This repo uses a single-context layout:
- GLOSSARY.md at the repo root.
- Architecture decision records in docs/adr/.

Before exploring the codebase, read GLOSSARY.md and ADRs relevant
to the area being investigated.

If these files are absent, proceed silently. Domain-modeling creates
them when terminology or decisions are resolved.

Use glossary terms consistently in issues, proposals, hypotheses,
tests, and code. Reconsider unfamiliar terminology; flag real gaps
for domain-modeling.

If a proposal contradicts an ADR, identify the ADR and explain why
the decision should be reopened.
